# 測試缺口風險地圖

綜合程式變更、實際使用與事故紀錄，定位未覆蓋的高風險測試路徑。

**產業別：**資訊科技　|　**系統類型：**analytics-bi

## 功能模組

- **關鍵路徑建模** — 建立跨前端、API、服務與資料層的使用者操作路徑。
- **變更熱區分析** — 依提交頻率、程式複雜度與近期修改辨識不穩定區域。
- **實際流量加權** — 用功能使用率、交易量與客戶層級衡量路徑重要性。
- **事故關聯回溯** — 將歷史事故、缺陷與回滾事件映射至程式及測試路徑。
- **缺口風險地圖** — 綜合覆蓋、變更、流量與事故，呈現未測路徑優先級。
- **測試投資規劃** — 推薦新增或強化的測試案例，估算風險降低與執行成本。

## 適合誰使用

- 工程主管
- 開發者
- 測試

## 運作流程

1. 建立產品路徑
2. 辨識變更熱區
3. 套用使用權重
4. 關聯事故紀錄
5. 審閱測試缺口
6. 核定測試投資
