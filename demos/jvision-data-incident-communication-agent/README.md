# 資料事件溝通 Agent

> 依資料事件影響持續發布進度、替代方案與復原通知，提升處置透明度。

依資料事件影響持續發布進度、替代方案與復原通知，提升處置透明度。

**產業別：**數據分析　|　**系統類型：**operations-console

## 功能模組

- **事件影響辨識** — 解析故障管線、受影響資料產品、報表與使用者群組。
- **受眾分級管理** — 依資料使用情境、業務重要度與地區建立通知受眾層級。
- **替代資料建議** — 尋找可用的備援資料集、舊版報表或臨時查詢路徑。
- **進度訊息編排** — 依事件階段產生具影響範圍、處理進度與預估時間的訊息。
- **多管道發布台** — 協調郵件、即時通訊、服務入口與資料目錄的發布時點。
- **復原確認通知** — 驗證資料新鮮度與品質恢復後，發布復原及後續注意事項。

## 適合誰使用

- CDO
- 資料工程師
- 資料管理員

## 運作流程

1. 建立事件摘要
2. 分析受影響對象
3. 準備替代方案
4. 審閱通知內容
5. 發布分階段進度
6. 確認復原結案

## 導入效益

- 報表產出工時：16小時 → **1小時**
- 異常發現時效：3天 → **1天**
- 資料覆蓋率：55% → **92%**
- 決策反應時間：5天 → **1天**
