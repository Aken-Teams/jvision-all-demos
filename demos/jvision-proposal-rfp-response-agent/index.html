2.3 知識庫資料分級、審核與發布機制

JVision 建議採用「建立、審查、發布、監測、汰除」五階段治理流程，並依資料敏感度區分公開、內部、機密三級。每筆知識均保留擁有者、核准人、生效日與下次複核日，確保內容可追溯且符合權責分工。[核准素材 KB-024]

內容審核與權限控管

一般作業知識採業務單位初審、知識管理人員複審；涉及法遵、產品條款或客戶權益者，則加會法務及產品負責人。發布後透過角色權限與資料標籤限制檢索範圍，所有查閱、編輯與核准行為皆寫入不可竄改的稽核紀錄。[ISO 27001 控制說明 v4]

品質監測與持續改善

平台將追蹤命中率、未解決查詢、內容回饋與逾期複核項目。建議每月召開治理會議，針對低信心回答及高頻未命中問題安排補強；正式上線後三個月的目標知識命中率為 ［待產品補入目標值］，並於維運月報揭露改善趨勢。

本機制可沿用客戶既有 Azure AD 身分體系，透過 SSO 與群組映射落實最小權限原則。相關介接方式將於藍圖階段完成盤點，並提供權限矩陣作為驗收依據。[金融客戶案例 CS-019]
