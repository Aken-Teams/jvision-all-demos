如果支付回呼重複送達，系統在哪裡去重？
主要在 WebhookInboxService 去重。
收到回呼後，系統以「供應商 + event_id」建立唯一鍵；若供應商沒有 event_id，則使用交易編號、事件類型與金額產生指紋。重複事件會保留接收紀錄，但不再推進支付狀態。

修改風險：不可只依交易編號去重，因同一交易可能合法產生授權、請款與退款等不同事件。調整唯一鍵前需回歸三個閘道 adapter。
