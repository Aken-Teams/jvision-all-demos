ADR-024 · Draft 3

採用代管事件匯流排與交易式 Outbox

狀態提議中
決策日期2026-08-21
決策擁有者平台架構小組

背景與問題

訂單服務目前透過同步 API 通知庫存、帳務與訊息服務。尖峰期間，下游逾時會占用訂單服務連線池並放大失敗，近六週已造成三次事件。企業客戶另要求 99% 狀態通知於 60 秒內送達並可完整追蹤。會議 8/18 §12:40 REQ-902

決策

採用代管 Kafka 相容事件匯流排，訂單服務以交易式 Outbox 寫入待發事件，再由獨立發送器投遞。所有消費端必須用業務事件 ID 實作冪等處理，失敗事件進入隔離佇列並保留 14 天。

理由

  • 隔離下游故障，避免同步逾時阻斷訂單核心交易。
  • 代管服務可在 8 週期限內提供跨區複寫與監控能力。
  • Outbox 同時保證業務資料與事件紀錄，不依賴分散式交易。

替代方案

同步 API + 重試協調器：導入較快，但無法消除運行期耦合。
自建 Kafka：控制權較高，但目前團隊缺乏 24×7 叢集維運能力。ARCH-317

預期後果

正面後果包含提升可用率、可重播事件及獨立擴展消費者；負面後果則是最終一致性、事件格式治理與每月平台費用增加。
