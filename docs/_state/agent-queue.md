# 題目候選（2026-08-23）

既有 1311 題｜本次產 40 題｜通過 20｜重複或不合格 1

## 通過的題目

1. **旅宿房務周轉協調台**（operations-console／餐飲旅宿）
   - 整合退房、清掃、複查、維修與可售房釋出作業，協助房務主管依入住時限安排人力，避免房況資訊落差造成旅客久候或房間閒置。
   - 差異：最像「旅宿布草周轉管理台」，但既有題目追蹤布草物流與庫存；本題管理客房從退房、清掃、修繕到重新可售的跨部門周轉。
   - repo：`jvision-hotel-housekeeping-turnover`
2. **旅宿早餐產能調度台**（operations-console／餐飲旅宿）
   - 依住房人數、團客時段與用餐券預估早餐尖峰，協調座位、餐檯補餐及服務人力，降低排隊、缺餐與閉餐後剩食成本。
   - 差異：最像「餐飲中央廚房備料台」，但既有題目管理跨據點備料；本題聚焦飯店早餐的住房需求、用餐分流、餐檯批次與現場座位產能。
   - repo：`jvision-hotel-breakfast-capacity`
3. **餐飲外送帳款核對台**（finance-ledger／餐飲旅宿）
   - 彙整各外送平台訂單、取消、折扣、廣告費與撥款明細，讓連鎖餐飲逐店核對應收差異、提出申覆並完成會計認列。
   - 差異：最像零售電商的「電商平台抽成對帳台」，但該題處理商品交易；本題專注餐飲外送的門市出餐、取消餐、即時促銷與平台配送責任。
   - repo：`jvision-restaurant-delivery-settlement`
4. **旅宿迷你吧耗用管制台**（warehouse-wms／餐飲旅宿）
   - 管理客房迷你吧的房內配置、補貨盤點、住客耗用與退房計價，協助房務和櫃台在結帳時限內釐清短少及免計爭議。
   - 差異：最像「餐廳備料耗損管制台」，但既有題目關注廚房原料耗損；本題管理客房迷你吧的房內配置、退房計價、收費爭議與補貨。
   - repo：`jvision-hotel-minibar-control`
5. **餐飲過敏原供餐管制台**（quality-qms／餐飲旅宿）
   - 集中管理菜單過敏原、顧客特殊需求、廚房防交叉接觸措施與出餐覆核，讓前場、廚房及主管留下完整供餐責任紀錄。
   - 差異：最像「餐飲食材出成率管制台」，但既有題目追蹤原料產出與成本；本題處理顧客過敏資訊、交叉接觸防護及每份特殊餐的出餐覆核。
   - repo：`jvision-restaurant-allergen-control`
6. **旅宿夜間營收稽核台**（finance-ledger／餐飲旅宿）
   - 協助飯店夜間班核對房費、餐飲掛帳、折讓、押金與付款批次，逐項處理跨日異常並產出可交接的日結營收報告。
   - 差異：最像「宴會場次毛利管制台」，但既有題目衡量單場宴會毛利；本題聚焦飯店全營業點跨日帳務平衡、房帳掛帳與夜間關帳。
   - repo：`jvision-hotel-night-audit`
7. **零售效期折價管制台**（warehouse-wms／零售電商）
   - 依門市批次效期建立巡檢、折價、下架與報廢任務，協助生鮮及食品零售降低過期風險，同時管控折價權限與毛利損失。
   - 差異：最像「電商活動庫存鎖定台」，但既有題目管理促銷期間可售數量；本題管理實體零售批次效期、巡架、階梯折價與下架報廢。
   - repo：`jvision-retail-shelf-life-control`
8. **連鎖門市調撥協同台**（warehouse-wms／零售電商）
   - 根據各店缺貨、滯銷與安全庫存提出跨店調撥建議，管理門市確認、揀出、在途、收貨及差異，提升現貨利用率並減少補貨等待。
   - 差異：最像「電商活動庫存鎖定台」，但既有題目預留平台活動庫存；本題在連鎖實體門市間媒合缺貨與餘貨，涵蓋雙方確認、交運及收貨。
   - repo：`jvision-retail-store-transfer`
9. **門市收銀差異調查台**（finance-case／零售電商）
   - 集中處理門市每日現金、刷卡、電子支付、禮券與退貨的收銀差異，保留班別調查、證據、覆核及帳務調整紀錄。
   - 差異：最像「電商結算爭議處理台」，但既有題目處理商家與平台間結算；本題追查實體門市每一班收銀、點交與多元支付短溢。
   - repo：`jvision-retail-cashier-discrepancy`
10. **電商退貨商品判定台**（operations-console／零售電商）
   - 將退回商品依外觀、包裝、配件及功能檢查結果，分流為重新上架、整新、折價、退供或報廢，並追蹤每筆價值回收。
   - 差異：最像倉儲物流的「退貨入庫與逆物流管理」，但既有題目著重退貨物流與庫存移動；本題核心是商品檢查分級、處置決策及價值回收。
   - repo：`jvision-ecommerce-return-disposition`
11. **零售陳列執行管理台**（operations-console／零售電商）
   - 把總部陳列圖、檔期指示與物料清單轉為門市任務，管理完工照片、缺件回報、覆核退件及區域達成率。
   - 差異：最像「電商商品刊登合規台」，但既有題目檢查線上商品頁內容；本題管理實體門市陳列圖落地、物料到店、照片驗證與返工。
   - repo：`jvision-retail-planogram-execution`
12. **物業廠商進場管制台**（security-soc／房地產與物業）
   - 管理維保、清潔與施工廠商的進場申請、人員名冊、保險文件、工作區域、門禁時段及離場點交，降低未授權作業風險。
   - 差異：最像「租戶裝修進場管制台」，但既有題目針對租戶裝修專案；本題涵蓋日常維保、清潔等短期廠商的人員資格、門禁與逐次離場。
   - repo：`jvision-property-vendor-access`
13. **商辦停車位配額管理台**（operations-console／房地產與物業）
   - 管理租戶固定、臨停與訪客車位配額，處理增減申請、候補排序、車號名冊、費用起訖及違規占用，提升有限車位使用效率。
   - 差異：最像「物業鑰匙借還管制台」，但既有題目管控實體鑰匙與借用責任；本題配置稀缺停車資源，並連結租戶配額、候補、車號及收費。
   - repo：`jvision-property-parking-allocation`
14. **租賃空置整備管理台**（maintenance-cmms／房地產與物業）
   - 在租戶退租後統籌點收、清運、修繕、清潔、驗收與招租交付，讓資產管理團隊縮短空置單元恢復可出租狀態的時間。
   - 差異：最像「建物點交缺失管理台」，但既有題目處理新建物交付缺失；本題管理既有租賃單元退租後的復原施工、成本責任與再次招租。
   - repo：`jvision-property-vacancy-make-ready`
15. **社區包裹代收管理台**（operations-console／房地產與物業）
   - 管理社區包裹到件、住戶通知、冷藏或大型件分區、逾期催領、領件核身及拒收退回，降低管理室堆積與誤領爭議。
   - 差異：最像「物業鑰匙借還管制台」，但既有題目追蹤可重複借還的鑰匙；本題處理大量一次性包裹的收件分區、通知、核身領取與逾期退回。
   - repo：`jvision-condo-package-room`
16. **工程疑義澄清管理台**（construction-pm／營建工程）
   - 集中管理工地對圖說、規範與施工介面的疑義提問，記錄送審、設計回覆、影響評估、現場指示及正式關閉，避免口頭答案失真。
   - 差異：最像「工程送審文件管制台」，但既有題目管理文件版次與送審狀態；本題以單一施工疑義為核心，串連圖面標註、正式答覆及現場驗證。
   - repo：`jvision-construction-rfi-control`
17. **分包估驗計價管理台**（construction-pm／營建工程）
   - 依分包契約項目管理當期申報數量、現場丈量、品質扣款、保留款與核定金額，讓工務、品管及成本人員完成一致的估驗流程。
   - 差異：最像「建案保固修繕管制台」，但既有題目追蹤完工後缺失修繕；本題管理施工期間分包商的完成數量、丈量、扣款與月度請款。
   - repo：`jvision-construction-subcontract-progress`
18. **工程材料樣品核定台**（construction-pm／營建工程）
   - 管理建材樣品從規格比對、送樣、設計審查、業主選色、封樣到進場核對，確保採購及施工使用的是已核定版本。
   - 差異：最像「工程送審文件管制台」，但既有題目偏重一般文件流轉；本題專門處理材料實體樣品的規格、色樣選擇、封樣版本及進場比對。
   - repo：`jvision-construction-material-approval`
19. **工種介面交接管制台**（construction-pm／營建工程）
   - 管理土建、機電、裝修等工種在同一作業面進退場前的條件確認、缺失整改、保護責任與正式交接，降低互相等待及成品破壞。
   - 差異：最像「臨時工程查驗管理台」，但既有題目驗證單一臨時設施安全；本題管理不同永久工程工種間的作業面條件、責任移轉與成品保護。
   - repo：`jvision-construction-interface-handover`
20. **診所爽約召回管理台**（healthcare-clinic／醫療照護）
   - 依療程重要性與爽約風險整理未到診名單，協助診所進行聯繫、改約、候補遞補及多次未回個案升級，維持照護連續性。
   - 差異：最像「醫療轉診追蹤管理台」，但既有題目追蹤跨院轉診是否完成；本題處理院所內預約爽約、重新召回與釋出時段候補遞補。
   - repo：`jvision-clinic-no-show-recall`
