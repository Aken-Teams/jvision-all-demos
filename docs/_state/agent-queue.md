## 通過的題目

1. **門市發票作廢覆核台**（finance-ledger／零售電商）
   - 集中收件門市作廢發票、原因、原票影像與重開資訊，依跨日、跨期及憑證缺漏分流覆核，讓總部財會在申報前完成追件、核准與稽核留痕。
   - 差異：最像既有「銷項發票作廢管制台」；本題限定連鎖門市原票回收、逐店追件及總部申報前覆核，不處理全公司的銷項作廢政策。
   - repo：`jvision-store-voided-invoice-review`
2. **電商退貨到倉判責台**（warehouse-wms／零售電商）

   - 差異：最像既有「門市退貨待驗處置台」；本題聚焦電商退貨到中央倉後的跨部門責任裁定與外部求償，不是門市暫存及退款交接。
   - repo：`jvision-ecommerce-return-liability`
3. **促銷檔期費用請款台**（finance-case／零售電商）

   - 差異：最像既有「通路上架費驗收台」；本題是零售商向供應商追收促銷贊助，核心為銷售門檻試算，不是驗收通路向企業請領的上架服務。
   - repo：`jvision-promotion-funding-claim`

   - 差異：最像既有「物流代收貨款清算台」；本題站在電商貨主端核對多家物流的貨到付款短溢及申訴期限，不管理物流商內部清算。
